# Задание 1. Автоматизация Black Myth: Wukong Benchmark Tool

Консольное приложение на **C# / .NET Framework 4.8**, Windows 10/11 x64.
Исходники находятся в `src`, собранное приложение — `bin/WukongRunner.exe`.
NuGet-пакеты не используются. Для OCR нужен отдельно установленный Tesseract 5 с английской моделью `eng`.

**Статус проверки:** приложение собирается; автоматические проверки перечислены в `VALIDATION.md`.
На компьютере подготовки Benchmark Tool не установлен. Поэтому управление его настоящим меню,
применение настроек и два игровых прохода **пока не проверены**. Решение нельзя представлять
как прошедшее сквозную проверку. При отличии интерфейса может потребоваться уточнить
названия пунктов/навигацию в `src/MenuDriver.cs`; программа останавливается с диагностикой.

## Подготовка и запуск

1. Установить бесплатный [Black Myth: Wukong Benchmark Tool в Steam](https://store.steampowered.com/app/3132990/).
   Нужен именно отдельный инструмент **AppID 3132990**, а не полная игра.
2. Войти в Steam. Один раз закончить установку необходимых компонентов, первоначальные
   диалоги Steam/лицензии и компиляцию шейдеров. Выбрать английский интерфейс Benchmark Tool,
   затем закрыть его. Приложение дополнительно передаёт `-culture=en` при запуске.
3. Установить [Tesseract OCR для Windows от UB Mannheim](https://github.com/UB-Mannheim/tesseract/wiki)
   с английским языком. Обычный путь: `C:\Program Files\Tesseract-OCR\tesseract.exe`.
4. Распаковать решение в доступную для записи папку. Запускать в обычном интерактивном
   сеансе Windows, с правами того же пользователя, что и Steam. Рабочий стол должен быть
   разблокирован. Закрыть оверлеи; во время работы не переключать окна и не управлять мышью.
5. Проверить зависимости и запустить из PowerShell в этой папке:

```powershell
.\bin\WukongRunner.exe --check
.\bin\WukongRunner.exe
```

Или дважды щёлкнуть `run.cmd`: при отсутствии EXE он сначала соберёт проект.
Остановка — **F12** или **Ctrl+C**. Если GPU не поддерживает полную трассировку:

```powershell
.\bin\WukongRunner.exe --gpu-rt off
```

Это явно выбранный вариант максимальной **растеризационной** нагрузки. По умолчанию RT включён;
программа не заменяет его незаметно на Off при ошибке или несовместимости.

Дополнительные параметры:

```powershell
.\bin\WukongRunner.exe --ocr "D:\Tools\Tesseract-OCR\tesseract.exe" --timeout 1200
.\bin\WukongRunner.exe --install "D:\SteamLibrary\steamapps\common\Black Myth Wukong Benchmark Tool"
.\bin\WukongRunner.exe --output "D:\BenchmarkResults"
```

`--install` должен соответствовать установке в манифесте Steam. `--timeout` — ограничение
ожидания запуска, меню или одного прохода, от 60 до 3600 секунд (по умолчанию 900).
`--check` проверяет наличие установки, EXE Tesseract и доступ к WMI; он не подтверждает работоспособность GUI/OCR.

## Выбор настроек

| Настройка | CPU-проход | GPU-проход |
|---|---|---|
| Режим | Windowed | Fullscreen |
| Разрешение вывода | 1280 × 720 | Максимальное по числу пикселей среди найденных в меню разрешений |
| Super Resolution Sampling | TSR | TSR |
| Super Resolution | 25% | 100% |
| Общий пресет при настройке | Low | Cinematic |
| View Distance Quality | Cinematic | Cinematic |
| Vegetation Quality | High | Cinematic |
| Прочие 8 отдельных параметров качества | Low | Cinematic |
| Full Ray Tracing | Off | On, уровень Very High; либо явно `--gpu-rt off` |
| Frame Generation | Off | Off |
| V-Sync / Framerate Cap | Off / Off | Off / Off |
| Motion Blur | Off | Off |

**CPU.** Малое разрешение и 25% линейного масштаба уменьшают количество рассчитываемых
пикселей приблизительно до 320 × 180. Низкое качество теней, освещения, отражений,
эффектов и текстур дополнительно снижает работу GPU. Большая дальность видимости и
повышенное качество растительности сохраняют больше объектов сцены и работы по подготовке
их отрисовки. CPU-проход получается ориентированным на процессор.

При этом любая игровая сцена использует и CPU, и GPU. На слабой видеокарте даже этот
набор не гарантирует упор в CPU; общая загрузка CPU также может быть невысокой при
упоре в один поток. Для доказательства ограничения нужна дополнительная телеметрия или
контрольный прогон с ещё меньшей графической нагрузкой. В отчёте не делается неподтверждённый
вывод «GPU исключён полностью».

**GPU.** Максимальное доступное разрешение, 100% масштаба, Cinematic и полная трассировка
Very High повышают нагрузку на шейдерные блоки, память и блоки трассировки GPU.
100% означает рендер в разрешении вывода без его снижения; TSR при этом остаётся методом
сглаживания. Frame Generation отключён, чтобы FPS не увеличивался искусственно вставленными
кадрами. V-Sync и лимит кадров отключены, чтобы не ограничивать результаты.
Motion Blur оставлен Off для обоих проходов: на основную тяжесть GPU-профиля влияют прежде
всего разрешение, освещение и трассировка; это контролируемый профиль, а не обещание
абсолютно максимального энергопотребления при любой конфигурации.

Максимум разрешения выбирается из значений, доступных текущему дисплею и драйверу в меню
(обход до 40 значений в каждую сторону с остановкой при повторе). Программа не создаёт
DSR/VSR-режимы в драйвере. Для 4K-нагрузки соответствующее разрешение должно быть доступно.
Если режим не применяется, проверка после перезапуска завершится ошибкой.

## Как устроена автоматизация

1. Читает путь Steam и `steamapps/libraryfolders.vdf`, затем `appmanifest_3132990.acf`.
   Проверяет отсутствие уже запущенной игры/бенчмарка. Второй экземпляр runner блокируется mutex.
2. Получает CPU, GPU, версию драйвера, RAM (общий объём и модули), ОС через `System.Management`/WMI.
3. Сохраняет исходные байты и атрибуты INI из конфигурационных каталогов установки
   `b1/Saved/Config/Windows` и `%LOCALAPPDATA%/b1/Saved/Config/Windows`.
   Журнал восстановления записывается **до** запуска игры.
4. Запускает Steam через `steam.exe -applaunch 3132990 -culture=en`.
   Параметр `-benchmark` не используется: сам по себе стандартный флаг UE не обещает запуск нужного сценария игры.
5. Находит элементы английского меню по OCR, выбирает значения клавишами и проверяет их текст.
   Ожидание ограничено. Произвольные непроверенные ключи в INI не дописываются.
6. Применяет настройки, перезапускает Benchmark Tool и заново читает каждый отдельный параметр.
   Это необходимо для настроек, требующих перезапуска. После изменения отдельных параметров
   пресет может называться Custom, поэтому проверяются сами значения качества.
7. Нажимает запуск бенчмарка и ждёт остановки движения сцены, после чего читает экран результатов.
   Во время движения сцены не запускается OCR: раз в секунду сравнивается маленькая сигнатура изображения.
8. Распознаёт Average / Minimum / Maximum FPS, проверяет `0 < min <= avg <= max`
   и совпадение двух последовательных чтений. При пропущенных или неоднозначных числах
   ожидает дальше, затем возвращает ошибку по тайм-ауту.
9. Повторяет сценарий для GPU. Измеряемых проходов ровно два; запуск для настройки не является проходом.
10. Закрывает только процессы из найденной папки Benchmark Tool и восстанавливает INI в `finally`.

Для поиска текста используется TSV Tesseract с координатами слов, а не фиксированные
экранные координаты. Однако алгоритм навигации всё равно зависит от интерфейса конкретной
версии игры; текущая реализация предполагает переключение значений стрелками Left/Right.
Если OCR не распознаёт меню, не следует считать такой запуск успешным.

## Результаты и восстановление

В `results/<UTC-время>/` создаются:

- `report.html` — читаемый отчёт: CPU/GPU/RAM, FPS обоих проходов, проверенные настройки, скриншоты;
- `report.json` — те же данные для машинной обработки;
- `CPU/`, `GPU/` — снимки экрана, текст OCR и TSV, включая `result.png`;
- `settings-before.json` — резервная копия исходных настроек.

Результат CPU сохраняется сразу: если GPU-проход завершится ошибкой, данные CPU останутся,
а общий статус будет `failed`. Код выхода: `0` — два результата и успешное восстановление,
`1` — ошибка/отмена во время проходов, `2` — неверные параметры или неготовое окружение.
Пользовательский список GPU выводится полностью: программа не утверждает, что WMI однозначно
определил активный адаптер рендеринга на ноутбуке с двумя GPU.

При аварийном завершении процесса/Windows сохраняется `settings-recovery.json` рядом с README.
Следующий запуск не перезапишет его. Закрыть игру и выполнить:

```powershell
.\bin\WukongRunner.exe --restore
```

Восстанавливаются только INI в двух известных каталогах. Сохранения, другие файлы и настройки
драйвера не удаляются. Если процесс игры не удалось закрыть, автоматическое восстановление
не производится, чтобы игра не перезаписала восстановленные файлы при выходе.

## Сборка и тесты

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Test
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\test-ocr.ps1
```

Первая команда использует `csc.exe`, входящий в Windows/.NET Framework, и не скачивает пакеты.
Также можно открыть `WukongRunner.csproj` в Visual Studio с .NET Framework 4.8 Developer Pack.
Вторая команда требует установленного Tesseract и проверяет **искусственную тестовую картинку**.
Её числа не являются результатом реального бенчмарка.

Для окончательной приёмки на целевой машине необходимо: выполнить обычный запуск; проверить
статус `complete`, два разных профиля в отчёте, совпадение трёх FPS со скриншотом каждого
прохода и `SettingsRestored=true`. Дополнительно проверить отмену F12 и несовместимый RT.
До этого этапа сквозная работоспособность не подтверждена.
