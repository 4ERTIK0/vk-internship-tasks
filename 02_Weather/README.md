# Задание 2. Погода по городам

Python **3.10+**, только стандартная библиотека. Устанавливать пакеты через pip не нужно.
В комплекте исходный `cities.txt`, скачанный из указанного в задании
[второго источника](https://gistpad.com/raw/vk-task-14). Основная ссылка:
[Облако Mail](https://cloud.mail.ru/public/LWcw/kpMqFgztw).

## Запуск

В терминале в этой папке:

```powershell
python weather.py
```

Либо `py -3 weather.py` в Windows, либо двойной щелчок по `run.cmd` при наличии Python в PATH.
Нужен доступ в интернет к `https://wttr.in`. Путь к стандартному `cities.txt` вычисляется
от расположения скрипта, поэтому запуск из другой рабочей папки тоже поддерживается.

Дополнительные варианты:

```powershell
python weather.py --cities "D:\Data\cities.txt"
python weather.py --download
python weather.py --timeout 30 --attempts 3 --output results
python -m unittest discover -s tests -v
```

`--download` обновляет файл городов из второго источника задания. Без этого флага используется
приложенная копия. Формат: UTF-8 (допустим BOM), один город на строку.

## Что делает

1. Загружает **весь** файл в память. Удаляет пустые строки и повторения, игнорируя регистр
   и лишние пробелы, сохраняет порядок первого появления города.
2. Для каждого уникального города выполняет запрос `https://wttr.in/{City}?format=j1`.
   Название URL-кодируется целиком, включая пробелы, кириллицу, `/`, `?`, `#`.
3. Разбирает JSON штатным модулем `json`. Берёт именно текущую температуру
   `current_condition[0].temp_C`, страну `nearest_area[0].country[0].value`.
4. Создаёт модель `WeatherData`: `city` (город), `temperature_c` (°C), `country` (страна).
   Дополнительно сохраняет `resolved_city` - найденный API населённый пункт - и время получения UTC.
5. Выводит все успешные города. Группирует по стране и вычисляет количество, среднее,
   минимум и максимум. Среднее = сумма текущих температур / число успешных городов страны.
6. Сохраняет исходные ответы API и отчёты в `results/<UTC-время>/`.

Для вычислений используется `decimal.Decimal`. Округление до двух знаков выполняется только
для печати. В JSON десятичные значения записаны строками, чтобы не потерять точность.

## Обработка ошибок

Запросы последовательные, с паузой 1 секунда. По умолчанию тайм-аут 20 секунд на запрос и
не более 3 попыток. Сетевые ошибки, HTTP 429 и 5xx повторяются с задержкой; HTTP 4xx,
кроме 429, не повторяются. `Retry-After` учитывается с ограничением паузы 30 секунд.
Отсутствующие поля, нечисловая температура и HTML вместо JSON дают явную ошибку.
Размер ответа ограничен 5 МБ.

Неуспешный город не получает выдуманную температуру `0` и не включается в статистику.
Программа продолжает обработку остальных городов, выводит `Успешно: N/M` и список ошибок.
Код выхода `0` означает полный результат; `1` — частичный результат; `2` — ошибку файла,
параметров/сохранения; `130` - Ctrl+C.

Геокодер wttr.in может выбрать соседний населённый пункт/район для указанного названия.
Поэтому исходное название не подменяется, а ответ геокодера сохраняется отдельно в `resolved_city`.
Например, в проверочном запросе для Saint-Petersburg API вернул ближайший пункт «Лахта».
Если список будет расширяться неоднозначными названиями, страну можно указывать прямо в строке файла.
